# Запуск в интернете

Дашборд открывается по ссылке у всей команды и закрыт общим паролем.
Все ключи хранятся в переменных окружения хостинга, а база, файлы документов и настройки — на постоянном диске `/data`.

Без `DASHBOARD_PASSWORD` сервер в сеть не запустится. Пароль должен быть не короче 10 символов. Придумать надёжный:

```bash
node -e "console.log(require('crypto').randomBytes(12).toString('base64url'))"
```

## Вариант 1. Railway

1. Загрузите проект в свой репозиторий на GitHub. Файл `.env` туда не попадёт: он в `.gitignore`.
2. railway.com → **New Project** → **Deploy from GitHub repo** → выберите репозиторий.
   Railway соберёт образ по `Dockerfile`; настройки сборки и проверки здоровья берутся из `railway.json`.
3. **Постоянный диск.** Откройте сервис → **Settings** → **Volumes** (или правой кнопкой по сервису → **Attach Volume**),
   путь монтирования — `/data`. Без диска база и документы пропадут при каждом обновлении.
4. **Переменные.** Сервис → **Variables** → добавьте:
   - `DASHBOARD_PASSWORD` — пароль команды;
   - `RAILWAY_RUN_UID=0` — нужно, чтобы приложение могло писать на диск (Railway монтирует тома от root);
   - ключи источников из `.env.example`, которые у вас есть: `WB_TOKEN`, `OZON_CLIENT_ID`, `OZON_API_KEY`, `ANTHROPIC_API_KEY` и другие.
   Переменные `HOST`, `PORT`, `DATA_DIR`, `SETTINGS_FILE` задавать не нужно: они уже есть в образе, а `PORT` Railway подставит сам.
5. **Ссылка.** Сервис → **Settings** → **Networking** → **Generate Domain**. Получится адрес вида `https://…up.railway.app`.
   Можно подключить и свой домен.
6. **Только одна копия сервиса** (Replicas = 1): Telegram-бот и база в файле рассчитаны на один экземпляр.

**Настройки бизнеса на Railway.** При первом запуске шаблон `settings.json` копируется на диск в `/data/settings.json`.
Править файл на диске неудобно, поэтому проще задать переменную `SETTINGS_JSON`: туда вставляется всё содержимое settings.json
одной строкой. Она важнее файла, а после её изменения Railway перезапустит сервис.

## Вариант 2. Свой сервер (VPS) с Docker

Нужен сервер с Docker и домен, который указывает на IP сервера (запись A).

```bash
git clone <ваш репозиторий> brandos && cd brandos
cp .env.example .env
nano .env        # DASHBOARD_PASSWORD, DOMAIN=dash.example.ru и ключи источников
docker compose up -d --build
```

- `docker-compose.yml` поднимает дашборд и Caddy. Caddy сам получает и продлевает HTTPS-сертификат для `DOMAIN`.
- Данные лежат в папке `./data` рядом с проектом: `db.json`, `files/`, `settings.json`, `session-secret`.
- Настройки бизнеса правятся в `./data/settings.json`, перезапуск не нужен.
- Обновление: `git pull && docker compose up -d --build`.
- Логи: `docker compose logs -f app`.

Без Docker: Node.js 20+, `npm ci --omit=dev`, переменные из `.env` с `HOST=0.0.0.0`, `TRUST_PROXY=1`, `COOKIE_SECURE=1`,
запуск `node server.js` через systemd или pm2. HTTPS обеспечивает nginx или Caddy перед ним.

## Резервные копии

Всё ценное лежит на диске `/data`. Достаточно копировать эту папку раз в день:

- свой сервер: `tar czf backup-$(date +%F).tgz data/` по cron;
- Railway: включите **Backups** у тома в настройках сервиса.

## Безопасность

- Ключи — только в переменных окружения хостинга или в `.env` на сервере. Не присылайте их в чат и не коммитьте.
- Сессия входа живёт 30 дней. Если сменить `DASHBOARD_PASSWORD`, сразу разлогинятся все.
- После 10 неверных паролей с одного адреса вход блокируется на 15 минут.
- Запросы, которые меняют данные, принимаются только со страниц самого дашборда.
- Файлы документов отдаются только после входа и открываются в «песочнице» браузера.
