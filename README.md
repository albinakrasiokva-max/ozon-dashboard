# BrandOS — дашборд селлера WB + Ozon

## Запуск

Нужен Node.js 20 или новее.

```bash
npm install               # SDK Claude, клиент IMAP и разбор писем
cp .env.example .env      # впишите ключи — в файле по шагам написано, где их взять
npm start                 # откройте http://localhost:3000
```

Без ключей дашборд работает на демо-данных. Если открыть `index.html` просто как файл, без сервера, тоже включается демо-режим.

## Как устроено

| Файл | Что делает |
|---|---|
| `server.js` | отдаёт `index.html` и API, запускает синхронизацию по расписанию |
| `lib/connectors/*.js` | по одному коннектору на источник: WB, реклама WB, Ozon Seller, Ozon Performance, amoCRM, Битрикс24, Т-Банк, Точка; документы — почта (IMAP), Диадок, документы WB |
| `lib/telegram.js` | Telegram-бот: принимает пересланные файлы и фото, отвечает, куда разложил |
| `lib/docs.js` | приём документов: файл → распознавание ИИ → задачи «подписать» и «оплатить» |
| `lib/ai.js` | Claude API (официальный SDK): распознавание документов в строгий JSON и ИИ-чат |
| `lib/snapshot.js` | снимок живых данных для ИИ-чата (без демо-цифр) |
| `lib/sync.js` | список источников, синхронизация и статусы с понятными ошибками |
| `lib/aggregate.js` | все расчёты дашборда |
| `settings.json` | цифры бизнеса, которых нет в API: план, себестоимость, расходы, график платежей, предельная ДРР |
| `data/db.json`, `data/files/` | данные из API; задачи, сделки, документы и решения команды; файлы документов |

Источник включается, только если в `.env` есть его ключ. Блок без подключённого источника помечается «демо».
Ошибки подключения видны на странице «Интеграции».

## Документы и ИИ

Документы приходят из пяти мест: почты (вложения новых писем), Telegram-бота (пересланные файлы и фото),
Диадока, кабинета WB и ручной загрузки на странице «Документы». Каждый файл сохраняется на сервере,
повторы отсекаются по содержимому.

Если задан `ANTHROPIC_API_KEY`, Claude читает PDF и фото и возвращает строгий JSON: тип, номер, контрагент, сумма,
дата, срок, нужна ли подпись, нужна ли оплата, раздел, краткое описание. Если нужна подпись или оплата —
создаётся задача со ссылкой на документ; исполнители берутся из `assignees` в `settings.json`.
Если модель откажется обрабатывать запрос, сервер API сам повторит его на рекомендованной модели (`fallbacks: "default"`).

ИИ-чат отвечает по живым данным: показатели, артикулы, реклама, деньги, задачи, сделки, документы.
Блоки без источника в чат не передаются — чат прямо говорит, каких данных нет. Без ключа чат отвечает по встроенным правилам.

Задачи, сделки и документы хранятся на сервере и общие для всей команды. Браузер отправляет изменения
по одному элементу, поэтому правки разных людей не затирают друг друга; новые документы подтягиваются раз в 30 секунд.

## Центр решений

Каждый день в `decisionHour` из `settings.json` (по умолчанию 8:00) и по кнопке «Пересчитать сейчас» сервер собирает полную картину
и составляет решения на сегодня. На вход идут: артикулы (выручка за 28 дней, тренд за 7 дней, продано, остаток, дни остатка,
реклама, ДРР, прибыль, маржа), рекламные кампании (расход, заказы, ДРР за месяц и за неделю, CTR, цена заказа), деньги и прогноз,
план, CRM, документы, задачи и прошлые ответы владельца на решения, включая причины отказов.

С ключом Claude список составляет ИИ по строгой JSON-схеме: направление, срочность, заголовок-действие, ситуация с цифрами,
что сделать и почему, 2–5 шагов, эффект в ₽ в месяц, срок, уверенность, метрика проверки. Сервер дополнительно проверяет ответ:
отбрасывает решения с одним шагом, приводит уверенность к 0–100 и не пускает сроки в прошлое.
Без ключа, или если ИИ не ответил, работают встроенные правила: дозаказ при остатке меньше `minStockDays` дней, кампании с ДРР выше
`maxDrr`, артикулы в минус, кассовый разрыв, отставание от плана, счета к оплате, сделки с выставленным счётом.

- **Принять** — каждый шаг становится задачей (исполнитель — `assignees` по направлению), прогресс считается по задачам;
  когда все задачи выполнены, решение переходит в «Выполнены».
- **Отложить на 3 дня** — через 3 дня решение вернётся в «Новые».
- **Отклонить** с причиной — тема не предлагается снова 14 дней, а причина передаётся ИИ при следующих разборах.
- **Обсудить с ИИ** — открывает чат с контекстом решения.

## Как считаются цифры

- **Выручка** — продажи WB (за вычетом возвратов) и выручка Ozon. Рост — к тем же дням прошлого месяца.
- **Прибыль** = выплаты маркетплейсов − себестоимость − реклама − (постоянные расходы + платежи из графика) пропорционально прошедшим дням месяца.
  Ozon отдаёт выплату только итогом за месяц, поэтому выплаты Ozon по дням и артикулам — оценка по доле из финансового отчёта (помечена ≈).
- **Маржа канала** — то же самое за 28 дней, но без постоянных расходов. **ДРР** = расход на рекламу / выручка.
- **Дней остатка** = остаток / (продано за 28 дней / 28).
- **Прогноз денег на 30 дней**: сегодняшний остаток в банке + средний дневной поток по выписке за 30 дней
  (без платежей из графика) − платежи из `settings.json` в свои даты. Коридор — разброс дневного потока.
  Кассовый разрыв — первый день, когда остаток уходит в минус.
- **Синхронизация** — каждые `syncMinutes` минут (из `settings.json`) и по кнопке «Обновить».

## Проверка

```bash
npm test         # 26 тестов: коннекторы, расчёты, документы, ИИ, Telegram, почта, Центр решений, сервер
npm run check    # понятный отчёт по расчётам на тестовых данных
```

Тестовые ответы лежат в `test/fixtures.js`. По ним проверены коннекторы WB (включая документы), рекламы WB, Ozon Seller,
Ozon Performance, amoCRM и Т-Банка, распознавание документов и чат (ответы Claude подменены), Telegram-бот и разбор писем.
Битрикс24, Точка, Диадок и само подключение к IMAP написаны по документации и на тестовых данных не прогонялись.
Каждый коннектор нужно сверить с личным кабинетом на реальном ключе.
